# Proposed 48-hour B200 plan

For an already reserved eight-B200 node, after parameter reconciliation and separate execution approval. All durations are proposed ceilings; keep a shared real reservation end across every run so retries/config changes cannot restart the paid window. Reserve export time in each run and stop on identity, fit, quality, accounting or retention failures.

| Hours | Tracks and decision |
|---|---|
| 0–4 | Inventory, license/access, immutable weights/runtime, generation and task smoke (E01) |
| 4–8 | Supported GPU/offload topology screen; separate fit, smoke and SLO milestones (E02) |
| 8–13 | Qualified engine common-control and best-bundle comparison (E03) |
| 13–20 | Scheduler/admission screen and coarse open-loop knee, refine selected boundary (E05–E06) |
| 20–26 | Sparse actual/max-context pairs and selected cache/session/tenant conditions (E07–E08) |
| 26–30 | Documented thinking modes; optional checkpoint format only if already qualified (E09/E04) |
| 30–42 | Matched quality/SLO repetitions and winner soak; exclude profiling (E10/E06) |
| 42–46 | Whole-node replicas/recovery proposal and full-window accepted-task/user cost (E12/E11) |
| 46–48 | Archive, independent destination verification, final receipts and reservation ledger |

Do not execute a full Cartesian product. Start native, choose informative contrasts, discard failed arms before enlarging samples, and use spare time for confirmation. Sparse screens are 2–5 minutes and carry no capacity claim. Proposed confirmation is three one-hour repeats plus a three-hour winner soak composed of bounded segments; retained finite trials do not establish indefinite stability or a statistical confidence interval.

The current collector handles endpoint requests and driver scheduling. Engine flag sweeps, GPU/offload placement, replicas, failure injection and recovery need a reviewed deployment procedure and their own authorization. If unavailable, mark the corresponding track pending and spend the time on supported evidence. A B200-compatible NVFP4 path remains conditional; NVFP8 and an unverified TensorRT-LLM engine are blocked. Text-only savings are a lower-priority conditional experiment; never delete checkpoint tensors as an optimization shortcut.

The example B200 file contains only a short baseline/stress proposal with unresolved corpus, qualification, end time and export. It is not the final reservation schedule or a representative capacity workload.
